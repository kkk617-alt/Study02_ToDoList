# 할 일 관리 앱 — PRD / 설계 문서

- 작성일: 2026-10-02
- 상태: 승인됨 (구현 계획 수립 대기)
- 문서 종류: 제품 요구사항 + 설계 결정 기록

---

## 1. 배경과 목적

하루 10~20개 규모의 개인 할 일을 한 화면에서 관리하는 웹앱을 만든다.

해결하려는 문제는 두 가지다. 첫째, 할 일을 적어두는 곳과 완료를 체크하는 곳이 흩어져 있으면 전체 상황이 안 보인다. 둘째, 업무·개인·공부가 한 목록에 섞이면 "오늘 공부를 아예 손대지 않았다" 같은 편중을 알아차리지 못한다.

따라서 이 앱의 목적은 **할 일 전체와 영역별 진행 상황을 한 화면에서 즉시 파악하는 것**이다. 기능의 수를 늘리는 것이 목적이 아니다.

## 2. 사용자와 사용 맥락

- 사용자: 작성자 본인 1명. 다른 사용자가 이 데이터를 보거나 수정하는 경우는 없다.
- 기기: 데스크톱 브라우저가 주 사용 환경. 모바일 폭에서도 깨지지 않아야 한다.
- 사용 리듬: 하루에 여러 번 짧게 연다. 아침에 10~20개를 몰아서 적고, 낮 동안 체크하고, 중간에 몇 개를 추가한다.
- 1회 사용 시간: 대부분 10초 미만. **추가와 체크가 빨라야 한다.** 이것이 다른 모든 편의보다 우선한다.

## 3. 성공 기준

1. 할 일 하나를 추가하는 데 2초 이내, 키보드만으로 가능하다.
2. 앱을 열면 전체 진행률과 카테고리별 진행률이 스크롤 없이 보인다.
3. 새로고침, 탭 종료, 브라우저 재시작 후에도 데이터가 그대로 남는다.
4. `index.html`을 더블클릭하면 실행된다. 설치·빌드·서버·네트워크가 필요 없다.
5. 외부 의존성이 0개다. `package.json`이 없다.

## 4. 범위

### 포함
- 할 일 추가, 제목 수정, 카테고리 변경, 삭제
- 완료 체크 / 해제
- 카테고리 분류: 업무 / 개인 / 공부 (3종 고정)
- 진행률: 전체 1개 + 카테고리별 3개
- 상태 필터(전체/진행중/완료) × 카테고리 필터(전체/업무/개인/공부)
- 삭제 되돌리기
- localStorage 영속화

### 제외 (의도적으로 넣지 않음)
마감일, 알림, 반복 할 일, 하위 작업, 메모·상세 설명, 우선순위·별표, 드래그 정렬, 검색, 태그, 다크 모드, 사용자 정의 카테고리, 기기 간 동기화, 계정·로그인, 통계 그래프, 데이터 내보내기/가져오기.

모두 "지금 필요하지 않다"는 판단이며, 필요해지면 그때 별도 요구사항으로 다룬다.

## 5. 핵심 설계 결정과 근거

구현 중에 이 결정들을 다시 흔들지 않기 위해 근거까지 기록한다.

### D-1. 날짜 개념 없는 단일 목록
할 일은 날짜 필드를 갖지 않는다. 하나의 목록에 계속 쌓이고, 완료하면 체크된다. "어제 못 끝낸 일"이라는 개념 자체가 없으므로 이월 규칙도 없다.

**근거**: 날짜별 분리는 미완료 항목 이월 규칙(자동/수동/폐기)을 반드시 정해야 하고, 그 규칙이 늘 어딘가 어색해진다. 날짜 없는 목록은 그 복잡성 전체를 제거한다.
**대가**: "오늘 10개 중 6개" 같은 하루 단위 성취감은 얻을 수 없다. 진행률은 전 기간 누적 지표다. (→ 13절)

### D-2. 완료 항목은 보존하고 필터로 숨긴다
완료해도 데이터는 삭제되지 않는다. 기본 필터가 '진행중'이라 목록에서 보이지 않을 뿐이다.

**근거**: 자동 삭제는 복구가 불가능하다. 기록을 남기는 쪽이 안전하다.
**대가**: 진행률 분모가 단조 증가한다. (→ 13절)

### D-3. 진행률은 필터와 무관하게 항상 전체 데이터 기준
'공부' 필터를 걸어도 진행률 영역의 숫자는 바뀌지 않는다.

**근거**: 필터를 바꿀 때마다 진행률이 흔들리면 지표로 신뢰할 수 없다. 필터는 "무엇을 볼지"를 바꾸는 도구이고, 진행률은 "실제 상태"를 말하는 지표다. 두 역할을 섞지 않는다. 카테고리별 편중은 필터가 아니라 카테고리별 진행률 3줄로 파악한다.

### D-4. 할 일은 제목과 카테고리만 갖는다
메모, 우선순위, 마감일 없음.

**근거**: 성공 기준 1(2초 내 추가)을 지키려면 입력 필드가 최소여야 한다. 필드는 나중에 추가하기 쉽지만, 한번 생긴 필드를 걷어내기는 어렵다.

### D-5. 단일 파일 `index.html`
CSS와 JS를 `index.html` 안에 인라인으로 포함한다.

**근거**: 파일 하나라 백업·전달이 쉽고, `file://`에서 아무 제약 없이 바로 열린다.
**대가**: 로직만 Node로 불러와 자동 테스트할 수 없다. 파일이 길어진다. 완화책은 10절(내부 구조 규칙)과 12절(수동 테스트 체크리스트)이다.

**검토했으나 선택하지 않은 안**: ES 모듈로 레이어를 분리하는 구조는 `<script type="module">`이 `file://`에서 origin `null`로 취급되어 CORS 정책에 막힌다. 실행할 때마다 로컬 서버가 필요해 성공 기준 4와 충돌한다.

## 6. 데이터 모델

localStorage 키 `todo-app-v1` 하나에 아래 객체를 JSON 문자열로 저장한다.

```js
{
  version: 1,
  todos: [
    {
      id: "1759363200000-k3x9f",   // 문자열. 생성 시각 + 랜덤 접미사
      title: "보고서 초안 쓰기",      // 문자열. 공백 트림 후 1자 이상
      category: "업무",              // "업무" | "개인" | "공부"
      done: false,                  // boolean
      createdAt: 1759363200000      // epoch ms. 정렬 기준
    }
  ]
}
```

### 규칙
- `version`을 처음부터 넣는다. 나중에 필드를 추가할 때 기존 데이터를 버리지 않고 마이그레이션할 수 있다.
- `id`는 `Date.now() + "-" + 랜덤문자열`로 만든다. 같은 밀리초에 두 개를 추가해도 충돌하지 않는다.
- 저장 순서는 `createdAt` 오름차순(추가된 순서)이며, 화면 표시 순서도 같다. 완료 항목을 아래로 밀거나 재정렬하지 않는다 — 항목이 눈앞에서 움직이면 체크하려던 대상을 놓친다.
- 상태가 바뀔 때마다 즉시 전체를 직렬화해 저장한다. 20개 규모에서 1ms 수준이므로 부분 저장이나 디바운스는 넣지 않는다.
- **필터 상태는 저장하지 않는다.** 새로고침하면 기본값(진행중 + 전체 카테고리)으로 돌아간다. 매번 열 때 "지금 할 일"이 보이는 것이 직전 필터를 기억하는 것보다 낫다.

## 7. 기능 요구사항

구현 계획이 참조할 수 있도록 ID를 부여한다.

### FR-1 할 일 추가
- 입력창 + 카테고리 선택 드롭다운 + 추가 버튼으로 구성한다.
- Enter 키 또는 추가 버튼으로 추가된다.
- 제목을 트림한 결과가 빈 문자열이면 추가하지 않는다. 입력창을 짧게 흔들고 포커스를 유지한다. 알림창은 띄우지 않는다.
- 추가 후 입력창만 비우고 **카테고리 선택은 유지한다.** 같은 카테고리를 연달아 넣는 것이 일반적이다.
- 추가 후 입력창에 포커스를 유지해 연속 입력이 가능하다.
- 새 항목은 목록 맨 아래에 추가된다.

### FR-2 제목 수정
- 제목 텍스트를 클릭하면 그 자리에서 입력 필드로 바뀌고, 기존 제목이 채워진 상태로 전체 선택된다.
- Enter 또는 포커스 이탈 시 저장한다. Esc는 취소하고 원래 제목을 되돌린다.
- 트림 결과가 빈 문자열이면 **취소로 처리한다. 삭제하지 않는다.** 실수로 지운 것과 삭제 의도를 구분해야 한다.

### FR-3 카테고리 변경
- 각 행의 카테고리 배지를 클릭하면 세 카테고리를 나열한 작은 드롭다운이 열리고, 하나를 선택하면 즉시 적용된다. 클릭할 때마다 다음 카테고리로 순환하는 방식은 사용하지 않는다 — 원하는 값에 도달하려고 여러 번 눌러야 하고 되돌리기가 어렵다.
- 변경 시 출발 카테고리와 도착 카테고리의 진행률이 모두 갱신된다.

### FR-4 삭제
- 행의 삭제 버튼을 누르면 확인 없이 즉시 목록에서 제거한다.
- 화면 하단에 "삭제됨 · 되돌리기"를 5초간 띄운다. 되돌리기를 누르면 **원래 위치에 동일 내용으로 복구한다** (복구를 위해 삭제된 항목과 그 인덱스를 보관한다).
- 5초가 지나면 알림이 사라지고 되돌릴 수 없다.
- 연속 삭제 시에는 가장 최근 삭제 1건만 되돌릴 수 있다.

**근거**: confirm 다이얼로그는 10~20개를 빠르게 정리하는 흐름을 매번 끊는다. 되돌리기는 흐름을 끊지 않으면서 오클릭 복구는 더 확실하다.

### FR-5 완료 체크
- 실제 `<input type="checkbox">`를 사용한다. 키보드와 스크린리더에서 그냥 동작한다.
- 완료 항목은 제목에 취소선을 넣고 흐리게 표시한다.
- 기본 필터가 '진행중'이므로 체크하면 목록에서 사라진다. 이는 의도된 동작이다.
- '완료' 또는 '전체' 필터에서 체크를 해제하면 진행중으로 되돌아간다.

### FR-6 필터
- 상태 축: 전체 / 진행중 / 완료
- 카테고리 축: 전체 / 업무 / 개인 / 공부
- 두 축은 독립적으로 조합된다 (예: 진행중 + 공부).
- 기본값: 진행중 + 전체 카테고리
- 필터 결과가 0건이면 조건에 맞는 안내 문구를 보여준다 (예: "진행중인 공부 할 일이 없습니다").

### FR-7 진행률
- 전체 진행률: 진행 바 + `완료수/전체수` + 백분율(정수 반올림)
- 카테고리별 진행률: 업무/개인/공부 각각 짧은 바 + `완료수/전체수`
- D-3에 따라 필터 상태와 무관하게 항상 전체 데이터로 계산한다.
- 분모가 0이면 `0/0 0%`와 빈 바를 표시한다. `NaN`이나 `Infinity`가 화면에 나와서는 안 된다.
- 카테고리별 완료수의 합과 전체수의 합은 항상 전체 진행률과 일치한다.

### FR-8 영속화
- 모든 변경(추가/수정/카테고리 변경/삭제/되돌리기/완료 토글)을 즉시 localStorage에 반영한다.
- 앱 시작 시 localStorage에서 읽어 복원한다.
- 저장 실패와 데이터 손상 처리는 11절을 따른다.

## 8. 화면 설계

한 화면, 세로 스크롤만. 페이지 전환과 모달 없음.

```
┌─────────────────────────────────┐
│  할 일                           │
│  ┌───────────────────────┬────┐ │
│  │ 할 일 입력...          │업무▾│ │  ← Enter로 추가
│  └───────────────────────┴────┘ │
├─────────────────────────────────┤
│  전체  ████████░░░░  8/12  67%  │
│    업무 ██████░░ 3/5            │
│    개인 ████████ 4/4            │
│    공부 ░░░░░░░░ 1/3            │
├─────────────────────────────────┤
│ [전체][진행중][완료] [전체▾카테고리]│
├─────────────────────────────────┤
│ ☐ 보고서 초안 쓰기        업무 ✎🗑│
│ ☑ 장보기                 개인 ✎🗑│
│ ☐ 알고리즘 3문제          공부 ✎🗑│
└─────────────────────────────────┘
```

### 레이아웃 규칙
- 입력창과 진행률 영역은 성공 기준 2에 따라 스크롤 없이 보인다. 긴 목록은 아래로 스크롤된다.
- 최소 지원 폭 360px. 이 폭에서 가로 스크롤이 생기지 않는다. 카테고리별 진행률 3줄은 좁은 화면에서 세로로 쌓인다.
- 카테고리는 색으로 구분하되 **색만으로 구분하지 않는다.** 배지에 항상 글자(업무/개인/공부)를 함께 표시한다.
- 최대 본문 폭을 두어 넓은 모니터에서 한 줄이 과도하게 늘어나지 않게 한다.

## 10. 파일 내부 구조

`index.html` 한 개. D-5의 대가를 줄이기 위해 파일 안의 순서와 경계를 규칙으로 고정한다.

```
<style>   — [0] 디자인 토큰(색/간격/폰트) → [1] 레이아웃 → [2] 컴포넌트
<body>    — 정적 골격만. 목록 <ul>은 비워둔 상태로 둔다
<script>
  [1] STATE    todos 배열, 필터 상태, 되돌리기 보관함
  [2] STORAGE  load() / save()                — DOM 참조 금지
  [3] LOGIC    add/update/remove/toggle/진행률 계산 — DOM 참조 금지
  [4] RENDER   상태 → 화면. 전체 재그리기
  [5] EVENTS   목록은 이벤트 위임 하나로 처리
  [6] INIT     load → render
```

### 규칙
- **[2]와 [3]은 DOM을 참조하지 않는다.** 이 규칙이 "계산이 틀렸는지" 와 "표시가 틀렸는지"를 구분하는 유일한 수단이다. 이 경계가 무너지면 단일 파일 구조는 디버깅이 불가능해진다.
- [4]는 전체 재그리기로 구현한다. 20개 규모에서 부분 갱신은 과설계다. 단, 인라인 편집 중인 입력 필드는 재그리기에 의해 날아가지 않도록 처리한다.
- 목록의 클릭·변경 이벤트는 `<ul>` 한 곳에 위임한다. 행마다 리스너를 붙이지 않는다.
- [3]의 함수들을 `window.__app`에 노출한다. 브라우저 콘솔에서 직접 호출해 검증하기 위한 용도다 (12절).

## 11. 엣지 케이스와 오류 처리

| 상황 | 동작 |
|---|---|
| 저장된 데이터 없음 (첫 실행) | 빈 목록 + "첫 할 일을 추가해보세요" 안내. 진행률 `0/0 0%` |
| JSON 파싱 실패 (데이터 손상) | 원본 문자열을 `todo-app-v1.corrupt`로 옮겨 보관하고 빈 상태로 시작한다. 상단에 "저장된 데이터를 읽을 수 없어 새로 시작합니다" 배너를 띄운다. **조용히 삭제하지 않는다.** |
| 스키마가 예상과 다름 (배열이 아니거나 필드 누락) | 손상과 동일하게 처리한다 |
| localStorage 차단 (시크릿 모드, 설정) | 메모리에서만 동작하고 "이 창을 닫으면 데이터가 사라집니다" 경고 배너를 고정 표시한다. 기능은 정상 동작한다 |
| 저장 용량 초과 (`QuotaExceededError`) | "저장에 실패했습니다" 배너를 띄운다. 화면의 변경 내용은 되돌리지 않는다 (사용자가 다시 시도하거나 정리할 수 있게) |
| 빈 제목 추가 시도 | 추가하지 않고 입력창 흔들림 + 포커스 유지 |
| 수정 중 제목을 전부 지우고 저장 | 취소로 처리. 원래 제목 유지 |
| 매우 긴 제목 | 최대 2줄까지 표시하고 말줄임 처리 |
| 제목에 HTML/스크립트 문자열 입력 | `textContent`로 삽입하므로 그대로 문자로 표시되고 실행되지 않는다 |
| 같은 밀리초에 연속 추가 | `id`에 랜덤 접미사가 있어 충돌하지 않는다 |
| 필터 결과 0건 | 조건에 맞는 안내 문구 표시 (FR-6) |

## 13. 알려진 한계

D-1과 D-2의 결과로 발생하는 구조적 한계다. 설계 단계에서 인식하고 수용한 것이며, 결함이 아니다.

**진행률이 시간이 지나면 둔감해진다.** 완료 항목을 보존하므로(D-2) 분모가 단조 증가한다. 2~3개월 사용하면 진행률이 80%대에서 거의 움직이지 않아 "오늘 얼마나 했는가"를 알려주지 못한다.

그때 선택할 수 있는 방향은 세 가지다.

1. **완료 항목 일괄 삭제 버튼** — 가장 작은 변경. 사용자가 원할 때 분모를 직접 리셋한다. 기록은 사라진다.
2. **최근 N일 기준 진행률** — `completedAt` 필드를 추가해야 한다. 이런 확장을 염두에 두고 6절에서 `version`을 미리 넣어두었다. 기록을 보존하면서 지표를 되살린다.
3. **날짜 모델 도입** — D-1을 뒤집는다. 가장 큰 변경이며 미완료 항목 이월 규칙을 새로 정해야 한다.

**이 중 어느 것도 지금 구현하지 않는다.** 실제로 둔감해지는 것을 경험한 뒤에 결정하는 편이 낫다.

**데이터가 브라우저에 묶여 있다.** localStorage는 기기·브라우저별로 분리되며, 브라우저 데이터 삭제 시 함께 사라진다. 다른 기기에서는 보이지 않는다. 사용자 1명·개인용이라는 전제(2절)에서 수용한 제약이다. 백업이 필요해지면 JSON 내보내기/가져오기가 가장 작은 해결책이다.

## 14. 용어

- **할 일 (todo)**: 제목·카테고리·완료 여부를 가진 항목 하나
- **진행중**: `done === false`인 할 일
- **완료**: `done === true`인 할 일
- **진행률**: `완료수 / 전체수`. 백분율은 정수 반올림
- **상태 필터 / 카테고리 필터**: 독립적으로 조합되는 두 개의 표시 조건 (FR-6)
