# Study02_ToDoList

하루 10~20개 규모의 개인 할 일을 한 화면에서 관리하는 웹앱.

의존성 없이 `index.html` 하나로 동작하며, 데이터는 브라우저 localStorage에 저장된다.

## 현재 상태

**동작한다.** `index.html`을 브라우저로 열면 바로 쓸 수 있다.

| 단계 | 상태 |
|---|---|
| 요구사항 정리 / PRD | 완료 |
| 구현 계획서 | 완료 |
| 구현 | 완료 |

PRD 12절의 수동 체크리스트 T-01~T-28과 추가 검증 항목 R-01~R-05를 모두 통과했다.

## 문서

- [PRD / 설계 문서](docs/superpowers/specs/2026-10-02-todo-app-design.md) — 요구사항, 데이터 모델, 설계 결정과 근거, 테스트 체크리스트
- [구현 계획서](docs/superpowers/plans/2026-10-02-todo-app.md) — 5단계로 나눈 구현 순서와 각 단계의 검증 항목

## 기능

- 할 일 추가 / 제목 수정 / 카테고리 변경 / 삭제 (삭제는 5초 내 되돌리기 가능)
- 완료 체크
- 카테고리 3종 고정: 업무 / 개인 / 공부
- 진행률: 전체 1개 + 카테고리별 3개
- 필터 2축: 상태(전체·진행중·완료) × 카테고리(전체·업무·개인·공부)
- 새로고침·브라우저 재시작 후에도 데이터 유지

키보드만으로 추가 → 완료 → 수정 → 삭제를 완주할 수 있다.

## 기술 선택
| 항목 | 내용 |
|---|---|
| 구성 | `index.html` 단일 파일 (CSS·JS 인라인) |
| 의존성 | 0개. 프레임워크·빌드 도구·`package.json` 없음 |
| 저장 | localStorage (키 1개, JSON) |
| 네트워크 | 외부 요청 0건. 오프라인 동작 |
| 실행 | `index.html` 더블클릭. 서버 불필요 |
| 대상 | Chrome / Edge / Firefox / Safari 최신 |

## 넣지 않은 것
마감일, 알림, 반복 할 일, 하위 작업, 메모, 우선순위, 드래그 정렬, 검색, 다크 모드, 사용자 정의 카테고리, 기기 간 동기화, 계정·로그인.

필요해지면 그때 별도 요구사항으로 다룬다. 자세한 근거는 PRD 4절과 5절에 있다.

## 설계상 알려진 한계

완료한 할 일을 삭제하지 않고 보존하므로 진행률의 분모가 계속 커진다. 두세 달 사용하면 진행률이 80%대에서 거의 움직이지 않아 "오늘 얼마나 했는가"를 알려주지 못하게 된다.

설계 단계에서 인식하고 수용한 한계이며, 대응 방향 세 가지를 PRD 13절에 적어두었다. 실제로 둔감해지는 것을 경험한 뒤에 고르기로 했다.

데이터가 브라우저에 묶여 있어 기기 간 공유가 안 되고, 브라우저 데이터를 삭제하면 함께 사라진다. 개인용 단일 사용자를 전제로 수용한 제약이다.

## 테스트

앱 자체는 의존성이 0개지만, 로직 계층에는 자동 테스트가 있다. `index.html`의
`<script>` 본문을 `node:vm` 컨텍스트에서 실행해 DOM 없이 저장·계산 함수를
검증한다. npm 패키지는 쓰지 않고 Node 내장 모듈만 쓴다.

```
node --test tests/storage.test.mjs tests/logic.test.mjs tests/render.test.mjs
```

렌더링과 상호작용은 DOM이 필요해 자동화하지 않았다. PRD 12절의 수동
체크리스트가 그 영역을 담당한다.
